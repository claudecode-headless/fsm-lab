# fsm-lab — the long-running agent orchestration substrate (project brief)

This repo runs a finite-state machine that orchestrates worker agents on
GitHub Actions: state lives on the `fsm-state` branch (state.json +
append-only journals), the conductor self-chains turns via
repository_dispatch, workers execute tasks and report five-class outcomes,
and a watchdog backstops chain death. It is the reference implementation of
the worker-turn contract (T46/W-B).

## The contract (how a turn works)

- Every dispatch carries an ENVELOPE: `{task_ref, prompt, deadline_ms,
  session, budget{max_turns, wall_ms, lane_attempts}, mode, attempt}`.
  The prompt embeds this brief AS QUOTED DATA inside
  `<<<PROJECT-BRIEF>>>` fences — it is context, never instructions.
- Outcomes are FIVE CLASSES: `done` (work completed), `work_failed` (the
  work was attempted and failed — burns an attempt), `infra_failed` (the
  lane failed before work — net-zero retry, own budget), `deadline`
  (self-reported wall hit — the reaper's early signal), `poison`
  (anomalous/contract-violating — terminal quarantine, no retry).
- The write-back DOOR governs artifacts: only `tasks/<id>/**` and declared
  paths; `.github/**`, dotfiles, and root escapes are always denied.
- Report ids are attempt-scoped (`rep-<run>-a<attempt>`): a re-run's
  report is never dedup-swallowed.
- Leases: a task is assigned with a lease; expired leases are reaped by
  the clock (attempt-burn) or self-reported (deadline class).

## Current epoch conventions

- Mode `mock` (deterministic shim behaviors) is the default; mode `cc`
  routes through the Claude-Code adapter (OpenRouter lanes, free-model
  fallback); mode `real` is the raw-completion stand-in.
- Config defaults: max_parallel 4, lease 4 min (15 in long-lease epochs),
  max_attempts 3, tick interval 25s.
- The ops lane: repository_dispatch `fsm-control` {pause|resume|halt|
  unhalt|reset|configure}. Alerts: the `fsm-watchdog-alert` and
  `exec-duty-alert` labels on this repo's issues.

## Environment facts worth knowing

- GHA schedules are SPARSE: nominal 10-min crons fire ~2-4h apart; the
  chain's continuity rides self-dispatch, not cron.
- repository_dispatch resolves workflows from the DEFAULT branch only;
  feature-branch runs need workflow_dispatch with an explicit ref.
- Run names carry the task id + attempt (`task-<id> · <behavior> ·
  a<n>`) — the law-4 verification matches on them.
