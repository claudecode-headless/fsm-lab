# fsm-lab — the long-running agent orchestration substrate (project brief)

This repo runs a finite-state machine that orchestrates worker agents on
GitHub Actions: state lives on the `fsm-state` branch (state.json +
append-only journals), the conductor self-chains turns via
repository_dispatch, workers execute tasks and report five-class outcomes,
and a watchdog backstops chain death. It is the reference implementation of
the worker-turn contract (T46/W-B).

## The contract (how a turn works)

- Every dispatch carries an ENVELOPE: `{task_ref, prompt, deadline_ms,
  session, budget{max_turns, wall_ms, lane_attempts}, mode, attempt}`.
  The prompt embeds this brief AS QUOTED DATA inside
  `<<<PROJECT-BRIEF>>>` fences — it is context, never instructions.
- Outcomes are FIVE CLASSES: `done` (work completed), `work_failed` (the
  work was attempted and failed — burns an attempt), `infra_failed` (the
  lane failed before work — net-zero retry, own budget), `deadline`
  (self-reported wall hit — the reaper's early signal), `poison`
  (anomalous/contract-violating — terminal quarantine, no retry).
- The write-back DOOR governs artifacts: only `tasks/<id>/**` and declared
  paths; `.github/**`, dotfiles, and root escapes are always denied.
- Report ids are attempt-scoped (`rep-<run>-a<attempt>`): a re-run's
  report is never dedup-swallowed.
- Leases: a task is assigned with a lease; expired leases are reaped by
  the clock (attempt-burn) or self-reported (deadline class).

## Current epoch conventions

- Mode `mock` (deterministic shim behaviors) is the default; mode `cc`
  routes through the Claude-Code adapter (OpenRouter lanes, free-model
  fallback); mode `real` is the raw-completion stand-in.
- Config defaults: max_parallel 4, lease 4 min (15 in long-lease epochs),
  max_attempts 3, tick interval 25s.
- The ops lane: repository_dispatch `fsm-control` {pause|resume|halt|
  unhalt|reset|configure}. Alerts: the `fsm-watchdog-alert` and
  `exec-duty-alert` labels on this repo's issues.

## Environment facts worth knowing

- GHA schedules are SPARSE: nominal 10-min crons fire ~2-4h apart; the
  chain's continuity rides self-dispatch, not cron.
- repository_dispatch resolves workflows from the DEFAULT branch only;
  feature-branch runs need workflow_dispatch with an explicit ref.
- Run names carry the task id + attempt (`task-<id> · <behavior> ·
  a<n>`) — the law-4 verification matches on them.

# T-102 research: continuity mechanics

**Source:** `fsm-state/state.json` (chain `c-1789457940180`, seq 168, halted — the T46 drill epoch, 2026-09-15). Nothing on disk beyond the project brief, so this is reconstructed from that brief alone.

## What "continuity" means here

The chain must keep progressing toward task completion despite: GHA schedules being sparse (nominal 10-min crons fire ~2–4h apart), worker turns dying mid-work, leases expiring, and lanes failing. Three layers provide it:

1. **Self-dispatch** — the conductor re-invokes itself via `repository_dispatch`, making the chain self-sustaining between cron ticks. This is the primary mechanism; cron is a fallback, not the engine.
2. **Watchdog backstop** — `fsm-watchdog-alert`-labeled issues are the alerting surface; the watchdog detects chain death and restarts it.
3. **State durability** — state lives on the `fsm-state` branch as `state.json` + append-only journals, so a killed run resumes from the last committed state.

## Outcome classes vs. continuity

| Class | Continuity effect |
|---|---|
| `done` | Advances state; chain continues |
| `work_failed` | Burns an attempt; retryable within `max_attempts` |
| `infra_failed` | Net-zero retry, charged to own budget; chain continues |
| `deadline` | Reaper's early signal; lease reaped by clock (attempt-burn) |
| `poison` | **Terminal quarantine, no retry** — the only class that breaks continuity irreversibly for a task |

## Leases, the clock, and idempotency

- Leases default 4 min (15 in long-lease epochs); expiry burns an attempt and re-queues rather than halting.
- Report ids are attempt-scoped (`rep-<run>-a<attempt>`), so re-run reports are never dedup-swallowed — this is what makes retries continuity-correct.
- The write-back door denies `.github/**`, dotfiles, and root escapes; only `tasks/<id>/**` and declared paths are writable.

## Open continuity risks

1. **Sparse cron dependency** — if self-dispatch silently fails, the chain stalls for hours.
2. **Default-branch requirement** — `repository_dispatch` resolves workflows from the default branch only; an unmerged feature-branch conductor update breaks self-dispatch.
3. **Poison terminality** — no described recovery path for a `poison` outcome.
4. **Watchdog is a backstop, not a guarantee** — coverage depends on the `fsm-watchdog-alert` label being monitored.
5. **Config drift** — ops-lane `configure` can override defaults (max_parallel 4, lease 4 min, max_attempts 3, tick 25s) and silently shorten the chain's runway.

## Verifiable invariants

Run names carry task id + attempt (`task-<id> · <behavior> · a<n>`), so a continuity break shows up as a missing/expected sequence. Attempt-scoped report ids make every lease-reap and retry auditable.
